# FireTabs continuity

Before FireTabs work, read `docs/development/PROJECT-MEMORY.md`, then
`docs/development/NEXT-MILESTONE-PLAN.md` and the current header of
`docs/development/ACTIVE-WORK-QUEUE.md`. Follow current user direction over
historical plans. Dated experiment notes are history, not pending instructions.
For kernel work, use `docs/development/DOUGLAS-HARDWARE-CONTRACT.md` as the
central hardware/source reference before proposing changes or tests.

Use the direct GitHub connector. Preserve failed experiments in existing issues.
Do not ask resolved equipment/board-history questions again, describe old trials
as new strategies, or call source/emulator passes a tablet Linux boot.

Update the memory and current work header after a material result or owner
correction. Keep raw device data, identifiers and lab credentials out of Git.
